# v1.8 post-surgery LoRA token-weighted selector recheck

## Result

This recheck reruns the physical-pruning smoke from [the original record](v1.8-lora-post-surgery-smoke.md) with the token-weighted causal-target selector introduced in LoRA repair schema v5. It uses the same pinned model and WikiText revisions, split rows, seeds, pruning severity, rank, and training-step budget. The run used code at `ef907c0f42be96dc6815e339a9bb701c88ba57df`, which is included in the #756 merge commit.

Validation rows contain 128, 128, 76, and 66 valid tokens. Token-weighted selection chose step 16, improving validation loss from 2.96849 to 2.93568. The repaired model's held-out test loss was 3.52388, compared with 3.56788 after pruning without repair and 3.38628 for the source model. The repair therefore recovered 0.04400 loss versus no repair and remained 0.13760 worse than the source. The candidate artifact occupied 265,809,653 bytes across 10 files; the pinned source snapshot occupied 272,445,324 bytes across 10 files. The model width changed from 1,536 to 1,472 and parameter count fell by 2.47%.

The selected step stayed the same as in the earlier report, but its validation loss and saved artifact manifest differ. This is a separate run, not a replacement of the original record. It uses the same selected validation rows and confirms the result under the new aggregation rule. It is a single-seed, four-row feasibility check, not evidence of generalization or superiority. Short prefill timings are recorded in the JSON but are not a deployment-speed claim.

The first rerun attempt stopped before repair because PEFT was missing. After installing the declared PEFT version, an exploratory run completed with PyArrow 26.0.0; that version is outside the repository's `research` extra range and its output was not published. The final run below used the locked PyArrow 24.0.0.

## Reproduction

Use the pinned model in the local Hugging Face cache, install the `hf` and `research` extras, and run:

```powershell
uv sync --extra hf --extra research --locked
.venv\Scripts\python.exe tools/run_lora_post_surgery_study.py `
  --output docs/research/v1.8-lora-post-surgery-token-weighted-recheck.json `
  --remove-channels 64 --examples-per-split 4 --max-length 128 `
  --rank 2 --steps 16 --seed 42
```

The canonical JSON report is [v1.8-lora-post-surgery-token-weighted-recheck.json](v1.8-lora-post-surgery-token-weighted-recheck.json), SHA-256 `995d67f34ecbf62641a87d9c59e5c0574cd8d7ddfeff4a053250584acfcc7dda`.
