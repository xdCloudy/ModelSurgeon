# ModelSurgeon v2.0 scientific report and limitations

## Scope and claim boundary

This report closes the v2.0 documentation and audit boundary. It does not
claim that an autonomous optimizer has improved a model, generalized across
families, or produced a production-ready artifact. The checked-in evidence is
protocol, schema, deterministic decision, provenance, and fail-closed audit
evidence. Live optimization and benchmark results are explicitly untested.

The normative release record is
[`v2.0-autonomous-optimizer-release-v1.json`](v2.0-autonomous-optimizer-release-v1.json).
It classifies every declared surface as verified, experimental, unsupported, or
unknown and retains the reasons and reproduction boundary for each class.

## Supported findings

- The v2 benchmark protocol requires exact model, dataset, method, hardware,
  budget, seed, and metric identities and derives a deterministic protocol ID.
- Evidence cells retain measured, negative, unsupported, failed, and unknown
  outcomes. Terminal non-measured cells require a reason.
- Reference artifacts require mutation, repair, quantization, runtime, license,
  and rollback lineage. A prohibited or unavailable artifact cannot become a
  publication artifact.
- Publication is withheld for incomplete matrices, missing confidence-bounded
  evidence, unresolved critical audit findings, or failed replay.
- Objective constraints are evaluated before soft objectives; missing hard
  evidence is infeasible and missing soft evidence is not comparable.
- Optimize plans, approvals, resume cursors, and reproducibility packages are
  bounded control-plane records. Provider output does not become optimization
  authority or measured evidence.

These findings are supported by the typed contracts and tests named in the
release record. They are not model-quality findings.

## Research risks

- Selection bias, benchmark leakage, and tuning against held-out data could
  make an apparent improvement non-reproducible.
- Artifact, license, runtime, and hardware mismatches can invalidate a result
  even when a neighboring cell succeeds.
- Resource overruns, interrupted writes, and partial external tooling can
  produce incomplete evidence unless budgets and rollback state are retained.
- Confidence intervals from a small seed count do not establish task-general
  or deployment-general performance; claims remain bounded by the protocol.

## Negative results and unsupported cells

The release record intentionally retains the following negative boundary:

- No live v2 campaign was run in this repository state.
- No hosted provider, credentialed endpoint, or external model-quality service
  was used as evidence.
- Unlisted architectures, mutable revisions, unverified quantization/runtime
  combinations, and missing licenses remain unsupported or unknown.
- CUDA, llama.cpp, and external checkpoint results remain host-, tool-, and
  artifact-specific; absent dependencies are not replaced with estimates.
- No signed package, published model weight, or reference artifact is claimed.

An inconclusive or unavailable cell is retained as such. It must not be
converted into a success claim by aggregation, neighboring-family transfer, or
documentation wording.

## Untested claims

The following claims are intentionally untested and therefore absent from the
release boundary: autonomous quality improvement over a strong baseline,
cross-family or cross-size transfer, universal HF/GGUF/runtime support,
hardware-independent latency or memory benefit, hosted-provider optimization,
and production-wide reliability. A future campaign must preregister and measure
each claim before changing its capability state.

## Research protocol for a future campaign

Before collecting measurements, preregister exact checkpoint revisions and
licenses, held-out datasets/tasks/splits, autonomous and baseline/ablation arms,
hardware profiles, optimization/evaluation/artifact budgets, metrics and hard
thresholds, campaign seeds, repetition counts, and provenance fields. Preserve
source artifacts and stage outputs separately. Record every failure, timeout,
interruption, unsupported cell, and negative result.

Publish only when the complete matrix is present, all candidate claims point to
measured deployable cells with confidence intervals, the independent audit is
clean, replay passes, and the release artifact/license gate succeeds. If any
condition is missing, retain the bundle and report `withhold`.

## Reproduction commands

From a clean checkout with the project-managed runtime:

```text
uv sync --extra dev --locked
uv run --locked --extra dev python tools/audit_v20_release.py
uv run --locked --extra dev pytest tests/test_v20_release.py tests/test_v2_benchmark.py -q
```

The full repository gate is recorded in the release manifest. These commands
reproduce the offline contract checks only; they do not download models or
claim a live benchmark.
