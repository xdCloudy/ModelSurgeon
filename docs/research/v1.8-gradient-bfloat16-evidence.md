# BF16 streamed-gradient score comparison

This short follow-up checks the score changes under bfloat16 on the RTX 3060, where BF16 is supported. FP16 measurements are covered in the linked WikiText and model-scale records.

## Protocol

- Model: `Qwen/Qwen2.5-0.5B`, revision `060db6499f32faf8b98477b0a26969ef7d8b9987`.
- Calibration: first 1,024 tokens from the WikiText-2 raw training window documented in [the dataset follow-up](v1.8-gradient-wikitext-memory-evidence.md), calibration byte SHA-256 `dd19e768934268c03ddcf1e880debd6f862dbf23789a83e465f7aa3233ce4170`.
- Hardware/software: NVIDIA RTX 3060 12 GB, Python 3.14.7, PyTorch `2.14.1+cu130`, Transformers 5.10.1. Model and gradient storage use bfloat16; cross-entropy logits are fp32.
- Layers: 0 and 23, each with three paired retained-graph and streamed-backward allocator/score runs.
- Raw records: `v1.8-gradient-bfloat16-evidence-v1.json`.

## Results and interpretation

The incremental peak memory counters are unchanged from the matching fp16 shapes: streamed backward reduces peak incremental allocation by 73.68% at layer 0 and 59.29% at layer 23. The channel score rank correlations were 0.99999493 and 0.99998522; top 1% selections matched in both cases. Top 5% overlap was 99.59% at layer 0 (one channel differs) and 100% at layer 23.

Both gradient arrays and first-order score vectors fail strict `allclose(rtol=1e-4, atol=1e-6)`. Maximum absolute score differences were `5.59e-5` and `3.83e-4`. This confirms that lower-precision accumulation order can change a small number of boundary selections, even while overall ranking is highly correlated. It does not establish whether the one differing channel changes physical pruning quality.

This is one model and one short calibration window. It motivates reporting dtype and selection overlap when validating low-precision gradient collection; it does not establish a general BF16 ranking guarantee or quality/performance benefit.
