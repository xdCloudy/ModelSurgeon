# Goal-to-reality gap matrix

This matrix is the current implementation audit against `docs/goal.md`. It is
deliberately conservative: an item is not marked complete because a schema,
fixture, planner, or external adapter exists. It requires a first-party path
and retained evidence from the real model/runtime boundary.

| Goal requirement | Current evidence | Status | Remaining work |
| --- | --- | --- | --- |
| First-party autonomous execution | `HuggingFaceOptimizeRuntime` is the default executor for local/pinned HF causal models and now runs gated-MLP-channel, attention-head, transformer-layer, or rank-bounded Linear low-rank scopes selected in the structured search contract, with optional bounded LoRA or teacher-logit distillation repair and CPU-scoped dynamic-int8 quantization selected through structured contracts. An explicit native-GGUF runtime now routes only model-wide Llama/dense-Qwen MLP-channel plans to physical streaming surgery and pinned llama.cpp tools; incomplete or failed cells remain unsupported evidence. | Partial | Complete a time-bounded, accepted native-GGUF campaign and extend evidence to additional codecs, operations, runtimes, and quantization methods. |
| Real baseline measurement | `HuggingFaceMLPProofRuntime.baseline_measurement()` runs the pinned model over the local calibration corpus. The native-GGUF runtime also retained real SmolLM2-135M Q4_K_M perplexity, throughput, validation, source digest, hardware, and runtime-revision baseline evidence. | Partial | Add task-quality, memory, and deployment-runtime baselines to the general optimize contract and retain a completed native-GGUF child measurement. |
| Real candidate generation/search | Component-graph MLP, attention-head, and transformer-layer candidates are enumerated deterministically; architecture-aware features and physical in-memory measurements are retained for every supported scope; optional verified Meta-Surgeon predictions can order the supported MLP measurements. The v2 campaign physically measured all three MLP-channel candidates per held-out model. | Partial | Connect active-learning state and broader held-out transfer evaluation; measured outcomes remain authoritative over predictions. |
| Physical surgery and cumulative state | The first-party HF runtime executes bounded cumulative MLP-channel, attention-head, transformer-layer, or low-rank sequences, publishes a self-contained child with model, tokenizer, and method manifest files at every accepted step, reloads and smoke-tests each child, physically evaluates each reloaded child before acceptance, rolls back a violating child, rediscoveries the component graph/candidate features from each accepted child, records impossible post-child operations as stopping/negative evidence, uses fresh child measurements to choose the next edit within the budget, and rehydrates the selected child on process restart. The surgery `StageResult` now retains a structured sequence lineage with mutation IDs, source/parent/outcome IDs, artifact digests, state updates, and physical observation paths. Native GGUF writes now use the same source-immutable, streamed child boundary and retain failed external-runtime reload evidence, but no GGUF child has been promoted. Real attention-head and transformer-layer pretrained tranches were exercised and retained as strict-gate negative evidence without artifact promotion. | Partial | Produce a quality-feasible mixed-scope HF acceptance artifact where the declared contract permits it, complete a native-GGUF child validation, and extend lineage to every artifact-producing branch and container provenance. |
| Quality and deployment evaluation | Perplexity, per-child physical quality gates, forward timing, reload, inference smoke, repeated load time, prompt/decode throughput, latency, RAM/VRAM sampling, artifact size, and sample arrays are retained in stage evidence for the HF cell. | Partial | Add exact task metrics and format-specific deployment runtimes beyond the current PyTorch path. |
| Artifact lineage and immutability | Source tree and complete reloadable child-directory manifest digests, no-overwrite publication, digest-verified resume, orchestrator promotion checks, and structured parent/child lineage in the public surgery, repair, and quantization stage records exist. | Partial | Extend structured lineage to remaining artifact-producing branches and retain container provenance. |
| Repair and quantization | The first-party HF runtime can execute explicitly requested bounded LoRA or teacher-logit distillation arms on real calibration examples, publish a separate repaired child, reload it, remeasure it, and retain accepted/rejected evidence. It can also execute CPU-scoped dynamic-int8 quantization and rank-bounded low-rank projection surgery, publishing safe-tensors-plus-manifest artifacts, reloading them through first-party loaders, remeasuring them, and retaining accepted/rejected evidence. Native GGUF repair and additional quantization are explicitly unsupported in the bounded runtime. Accepted and rejected repair/quantization paths now retain structured parent/child artifact lineage with manifest digests. `repair.method: none` and `quantization.method: none` remain explicit controls. | Partial | Connect other format-specific quantization and GGUF only after real reload/evaluation evidence exists for each method. |
| Pareto selection and stopping | Orchestrator requires measured final Pareto evidence; the bounded runtime persists a Pareto archive over physically measured in-memory candidates, selects from the declared objective frontier when all required metrics are available, and records deterministic stopping for exhausted or physically impossible post-child candidates. Missing memory/disk objectives fail closed instead of being estimated. | Partial | Bind multiple reloadable/deployed frontier artifacts and richer objective confidence intervals into the public optimize result. |
| Hardware-grounded behavior | Hardware profiles and inventory exist; the runtime retains a live CPU/RAM/disk/CUDA inventory at profile, active-search, physical-surgery, artifact-write, and deployment boundaries, preflights measured RAM/disk capacity before candidate evaluation and each write, validates published artifact size, measures peak RAM/VRAM and disk size during deployment, and classifies unknown resource telemetry explicitly. | Partial | Retain per-operation hardware samples for every failure path and add format/runtime-specific resource validation beyond the current PyTorch path. |
| Stateful evidence flywheel | The first-party HF search retains real pre-mutation feature records for every measured candidate, publishes revision-keyed partitions through the atomic feature cache, records cache paths/checksums for original-state search and accepted-child rediscovery, and writes immutable optimization-evidence records containing model/dataset/hardware/configuration, features, predictions, measurements, outcomes, and lineage. Accepted, rejected, rolled-back, and failed search/child observations remain available for later audit. State-conditioned physical model evaluations select the next edit within the bounded HF sequence. `tools/prepare_real_surgeon_transfer.py` now converts only measured physical observations into a model-identity-grouped transfer dataset. | Partial | Expand the leakage audit to reusable multi-corpus training/query datasets, and ensure every runtime boundary retains explicit unsupported/unknown/inconclusive/OOM/timeout evidence. |
| Meta-Surgeon comparison | An optional signed, schema-checked Meta-Surgeon bundle can rank real candidates from retained pre-mutation features; the active-search record retains predictions, ordering, physical measurements, constraint outcomes, and regret for Meta-Surgeon, magnitude, random, and no-guidance baselines. The v2 regression pilot verified one signed bundle on held-out Qwen 0.5B and SmolLM2-135M cells, physically measuring all three candidate choices per cell, and produced negative transfer. An expanded 31-observation safety-classifier pilot matched the feasible best on SmolLM2 but selected an ineligible Qwen candidate; held-out AUC was 0.375. | Partial | Add substantially more source families, sizes, corpora, and hardware/runtime cells, improve calibration and state-aware features, and require demonstrated positive transfer before treating Meta-Surgeon as an optimization advantage. |
| Conversational control | Confirmed chat plans route through the same first-party runtime as direct optimize execution, with canonical campaign state and approval evidence. | Partial | Extend chat-executable coverage as additional model formats, operations, and task metrics gain real runtime evidence. |
| Independent acceptance campaign | Fresh revision-pinned campaigns ran the complete first-party workflow under a strict 0.99 quality-retention contract. Public tiny Llama and Mistral cells completed with physically smaller, reloadable accepted artifacts, cumulative accepted surgery, deployment measurements, and measured Pareto archives. Pretrained `HuggingFaceTB/SmolLM-135M`, `Qwen/Qwen2.5-0.5B`, and `HuggingFaceTB/SmolLM2-135M` cells also completed that path on the bounded CPU environment; the v2 Qwen and SmolLM2 cells each accepted two sequential rediscovered-state channel surgeries with reload and deployment measurements. A pretrained `TinyLlama-1.1B-Chat-v1.0` cell failed closed at active search when its declared RAM envelope could not admit the candidate working set. The independent rank-1 low-rank tranche reached active search on tiny Llama and Mistral but retained both as no-feasible cells under the strict quality gate. Attention-head and transformer-layer tranches exercised two pretrained cells each and retained strict-gate failures without artifact promotion. Companion GPT-2 evidence failed at profile with retained unsupported-architecture evidence rather than being promoted. The raw runs and the negative/neutral Meta-Surgeon transfer results are summarized in [first-party HF acceptance evidence v3](first-party-hf-acceptance-evidence-v3.json), [attention-head evidence](first-party-hf-acceptance-evidence-v4.json), and [transformer-layer evidence](first-party-hf-acceptance-evidence-v5.json). | Partial | Repeat across more pretrained families, runtime/hardware configurations, and task-specific quality metrics; add task-quality and non-PyTorch runtime evidence. This tranche still does not establish production-scale coverage. |

The default optimize path therefore remains an experimental, bounded verified
cell. This document must be updated after each real acceptance tranche; it is
not a substitute for that evidence.
