# Goal-to-reality gap matrix

This matrix is the current implementation audit against `docs/goal.md`. It is
deliberately conservative: an item is not marked complete because a schema,
fixture, planner, or external adapter exists. It requires a first-party path
and retained evidence from the real model/runtime boundary.

| Goal requirement | Current evidence | Status | Remaining work |
| --- | --- | --- | --- |
| First-party autonomous execution | `HuggingFaceOptimizeRuntime` is the default executor for local/pinned HF causal models and now runs gated-MLP-channel, attention-head, or transformer-layer scopes selected in the structured search contract. | Partial | Extend the same evidence contract to low-rank, repair, quantization, and GGUF. |
| Real baseline measurement | `HuggingFaceMLPProofRuntime.baseline_measurement()` runs the pinned model over the local calibration corpus. | Partial | Add task-quality, memory, and deployment-runtime baselines to the general optimize contract. |
| Real candidate generation/search | Component-graph MLP, attention-head, and transformer-layer candidates are enumerated deterministically; architecture-aware features and physical in-memory measurements are retained for every supported scope; optional verified Meta-Surgeon predictions can order the supported MLP measurements. | Partial | Connect active-learning state and held-out transfer evaluation; measured outcomes remain authoritative over predictions. |
| Physical surgery and cumulative state | The first-party HF runtime executes bounded cumulative MLP-channel, attention-head, or transformer-layer sequences, publishes a self-contained child with model and tokenizer files at every accepted step, reloads and smoke-tests each child, physically evaluates each reloaded child before acceptance, rolls back a violating child, rediscoveries the component graph/candidate features from each accepted child, records impossible post-child operations as stopping/negative evidence, uses fresh child measurements to choose the next edit within the budget, and rehydrates the selected child on process restart. | Partial | Bind the full dynamic parent/child sequence into the public optimize artifact record and connect mixed attention/layer/low-rank edit sequences to one search campaign. |
| Quality and deployment evaluation | Perplexity, per-child physical quality gates, forward timing, reload, inference smoke, repeated load time, prompt/decode throughput, latency, RAM/VRAM sampling, artifact size, and sample arrays are retained in stage evidence for the HF cell. | Partial | Add exact task metrics and format-specific deployment runtimes beyond the current PyTorch path. |
| Artifact lineage and immutability | Source tree and complete reloadable child-directory manifest digests, no-overwrite publication, digest-verified resume, and orchestrator promotion checks exist. | Partial | Bind the full parent/child manifest sequence and container provenance into the public optimize artifact record. |
| Repair and quantization | Existing libraries contain separate contracts and experiments; the first-party HF runtime now records explicit `unsupported` boundary observations for these stages instead of treating them as successful operations. | Not connected | Connect only after real reload/evaluation evidence exists for each format and method. |
| Pareto selection and stopping | Orchestrator requires measured final Pareto evidence; the bounded runtime persists a Pareto archive over physically measured in-memory candidates, selects from the declared objective frontier when all required metrics are available, and records deterministic stopping for exhausted or physically impossible post-child candidates. Missing memory/disk objectives fail closed instead of being estimated. | Partial | Bind multiple reloadable/deployed frontier artifacts and richer objective confidence intervals into the public optimize result. |
| Hardware-grounded behavior | Hardware profiles and inventory exist; the runtime retains a live CPU/RAM/disk/CUDA inventory at profile and deployment boundaries, measures peak RAM/VRAM and disk size during deployment, and retains classified unsupported/failed boundary evidence. | Partial | Enforce availability and disk headroom before mutation, retain per-operation hardware samples for every failure path, and add format/runtime-specific resource validation beyond the current PyTorch path. |
| Stateful evidence flywheel | The first-party HF search retains real pre-mutation feature records for every measured candidate, publishes revision-keyed partitions through the atomic feature cache, records cache paths/checksums for original-state search and accepted-child rediscovery, and writes immutable optimization-evidence records containing model/dataset/hardware/configuration, features, predictions, measurements, outcomes, and lineage. Accepted, rejected, rolled-back, and failed search/child observations remain available for later audit. State-conditioned physical model evaluations select the next edit within the bounded HF sequence. | Partial | Convert the retained post-mutation observations into leakage-audited reusable training/query datasets, and ensure every runtime boundary retains explicit unsupported/unknown/inconclusive/OOM/timeout evidence. |
| Meta-Surgeon comparison | An optional signed, schema-checked Meta-Surgeon bundle can rank real candidates from retained pre-mutation features; the active-search record retains predictions, ordering, physical measurements, and regret for Meta-Surgeon, magnitude, random, and no-guidance baselines. | Partial | Run equal-budget held-out model/family/hardware comparisons and retain transfer, search-regret, and frontier results, including negative results when guidance does not improve the measured baseline. |
| Conversational control | Confirmed chat plans route through the same first-party runtime as direct optimize execution, with canonical campaign state and approval evidence. | Partial | Extend chat-executable coverage as additional model formats, operations, and task metrics gain real runtime evidence. |
| Independent acceptance campaign | Unit/fixture coverage is broad; no fresh multi-family end-to-end acceptance campaign has been claimed. | Not complete | Run and retain fresh evidence across multiple model families/configurations, including honest no-feasible cells. |

The default optimize path therefore remains an experimental, bounded verified
cell. This document must be updated after each real acceptance tranche; it is
not a substitute for that evidence.
