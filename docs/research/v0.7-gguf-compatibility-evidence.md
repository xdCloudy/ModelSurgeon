# v0.7 native GGUF compatibility evidence

## Claim boundary

Issue #161 is implemented as a complete matrix over four architecture families, two
whole-file storage profiles, and six operations. `Q4_K_M` is a llama.cpp file recipe rather
than a claim that every tensor has type `Q4_K`; mixed tensor types are expected.

The matrix has three non-failure states:

- `runtime_verified` is the only support claim. It requires a successful load and forward
  pass by llama.cpp commit `95b8e33e16bb9a60de780a70930ebf729db6a90a`, bound to the
  artifact SHA-256, GGUF metadata, source identifier, and immutable source revision.
- `structural_only` means focused native parser, architecture, codec, planner, or executor
  tests exist, but there is no post-operation external-runtime claim.
- `unsupported` makes an absent fixture or intentionally absent implementation explicit.

`failed` is reserved for a supplied runtime fixture that llama.cpp rejects. The scheduled
gate writes its report before failing, so the raw cell evidence remains available.

## Upstream drift detection

The weekly and manually dispatchable `GGUF compatibility` workflow builds the pinned
llama.cpp tools from source, downloads each immutable HF revision, converts the fixtures,
quantizes the Llama fixture, and runs the complete matrix. A converter failure, an unknown
GGUF version/type/metadata shape, a llama.cpp revision mismatch, or a load/forward failure
fails the job. Updating the shared upstream pin therefore cannot silently retain stale
compatibility claims.

This behavior was observed directly while selecting fixtures: pinned
`convert_hf_to_gguf.py` rejected
`HuggingFaceM4/tiny-random-LlamaForCausalLM@d3040b7c81a0a810fa13c6f392f3e304a0e121d5`
because its tokenizer declares the special `pad` token as `-1`. The preparation stage treats
that converter contract change as a hard failure; the suite does not patch or ignore it.

## Automated coverage

- `tests/test_gguf_compatibility.py` proves claim/evidence invariants, full Cartesian
  coverage, exact file-profile metadata checks, hashing, and scheduled-gate failure behavior.
- Existing focused GGUF tests exercise all architecture contracts, bounded parser behavior,
  native codecs, discovery, Llama/Qwen MLP and attention operations, generic layer removal,
  and selected-tensor low-rank replacement.
- `tools/run_gguf_compatibility.py` is the deterministic report/gate entry point;
  `tools/prepare_gguf_compatibility.py` creates the small pinned fixtures used in CI.
