# v1.8 physical-prune and LoRA repair smoke

## Result

A pinned SmolLM2-135M source checkpoint was physically pruned by removing the 64
lowest global gated-MLP channel scores (the sum across layers of gate-row L2 norm ×
up-row L2 norm × down-column L2 norm). The same channel indices were removed from
all 30 layers. Intermediate width changed from 1,536 to 1,472 and parameter count
fell from 134,515,008 to 131,197,248 (2.47%).

The original and candidate checkpoints were compared in FP16. Source and both
candidate artifact directories contained eight deployable files, including the
same tokenizer vocabulary. The no-repair checkpoint occupied 265,801,794 bytes
versus 272,437,465 bytes for the source: 6,635,671 fewer bytes (2.44%). The no-repair
and repaired checkpoints were both saved and reloaded before test evaluation.

On the four selected WikiText-2 test rows (508 next-token targets), mean token loss
was 3.38654 for the source, 3.56768 after pruning without repair, and 3.52391 after
LoRA. The held-out-selected LoRA checkpoint recovered 0.04378 loss versus no repair,
but remained 0.13736 worse than the source. Selection chose step 16, with validation
loss 3.10797 at the untouched step zero and 3.07365 at step 16. The adapter trained
122,880 parameters for 3.22 seconds; measured peak CUDA allocation during repair was
778,641,920 bytes.

This is a small, single-seed feasibility result, not evidence of broad quality
recovery or a competitive compression frontier. Prefill timings varied across
repeated runs, so this smoke makes no inference-speed claim.

## Provenance and protocol

- Model: [`HuggingFaceTB/SmolLM2-135M`](https://huggingface.co/HuggingFaceTB/SmolLM2-135M/tree/93efa2f097d58c2a74874c7e644dbc9b0cee75a2), revision `93efa2f097d58c2a74874c7e644dbc9b0cee75a2`; model card lists Apache-2.0.
- Dataset: [Salesforce WikiText](https://huggingface.co/datasets/Salesforce/wikitext/tree/00aa25585682d4957f9e86edc73f59be7419af99/wikitext-2-raw-v1), config `wikitext-2-raw-v1`, revision `00aa25585682d4957f9e86edc73f59be7419af99`; upstream metadata declares CC-BY-SA-3.0 and GFDL. The dataset is attributed to [Merity et al., 2016](https://arxiv.org/abs/1609.07843). Raw text is not included in the report; all three split file digests, selected row indices, and text digests are recorded.
- Train, selection, and test examples come from their corresponding distinct dataset splits. The selected token sequences were checked for exact identity across splits. Test examples were not used for checkpoint selection.
- Repair targets all 30 `model.layers.*.mlp.down_proj` modules with rank 2, alpha 4, learning rate 0.001, 16 maximum steps, and seed 42. PEFT is the existing Apache-2.0 optional integration; this study copies no upstream code.
- Runtime: Python 3.12.14, PyTorch 2.14.1+cu132, Transformers 5.10.1, PEFT 0.21.2, PyArrow 24.0.0; NVIDIA RTX 3060 12 GB.
- Two full runs reproduced the pruning indices, LoRA adapter and loss traces, candidate artifact manifests, and source/no-repair/repaired test losses. Hardware timing and wall-clock telemetry varied between runs.

## Reproduction

The model checkpoint is expected in the local Hugging Face cache. `research` installs
the optional Parquet reader; install a CUDA-enabled PyTorch build for the target GPU
using the [official PyTorch selector](https://pytorch.org/get-started/locally/).

```powershell
uv sync --extra hf --extra research --locked
.venv\Scripts\python.exe tools/run_lora_post_surgery_study.py `
  --output docs/research/v1.8-lora-post-surgery-smoke.json `
  --remove-channels 64 --examples-per-split 4 --max-length 128 `
  --rank 2 --steps 16 --seed 42
```

The canonical report is [`v1.8-lora-post-surgery-smoke.json`](v1.8-lora-post-surgery-smoke.json), SHA-256 `cba2f7b28c38e2b6174dcee82ca4297cd5dd4eb9c2a82efb3974db10a6dfa41a`.
