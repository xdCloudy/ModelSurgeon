# WikiText-2 gradient streaming memory follow-up

This follow-up checks whether the memory reduction and channel-removal ranking agreement from the initial synthetic calibration spike also appear on natural calibration text and at different depths in the same real Hugging Face model. It does not change or reinterpret the earlier synthetic result.

## Protocol

- Model: `Qwen/Qwen2.5-0.5B`, immutable revision `060db6499f32faf8b98477b0a26969ef7d8b9987`.
- Dataset source: `Salesforce/wikitext`, `wikitext-2-raw-v1`, training member only. Source archive SHA-256 `ef7edb566e3e2b2d31b29c1fdb0c89a4cc683597484c3dc2517919c615435a11`; extracted `wiki.train.raw` SHA-256 `6707892fa3788b5ab9ed78ab5ff37d9fe825f6011a2ad4fcd6a6d467f0e7da57`. No WikiText validation or test split was used.
- Hardware/software: NVIDIA GeForce RTX 3060 12 GB; Python 3.14.7 environment; PyTorch `2.14.1+cu130`; Transformers 5.10.1.
- Precision and workload: fp16 weights, fp32 logits for cross-entropy, 1,024 tokens in eight 128-token chunks (1,016 causal targets), layer-local MLP projection gradients. Each record compares three retained-graph runs with three streamed-backward runs, alternating execution order.
- Calibration windows: first 1,024 tokens from the training file for layers 0, 12, and 23; plus 1,024-token windows from 100,000-character training-text excerpts starting at character offsets 4,000,000 (layer 12) and 8,000,000 (layer 0). Exact input byte hashes and complete per-run counters are in the JSON record.
- Benchmark implementation: `tools/benchmark_gradient_graph_memory.py`, SHA-256 `57518e50e9b6fd4666529bf2e95ca260ccc30d23ce00410af3921637e0bbfb95`, at source revision `90f1deeaf95c9ad46f4592d8474d1b3f05cafdd7`.

In all five records the strict fp16 gradient-array and first-order-score `allclose(rtol=1e-4, atol=1e-6)` checks fail, while top 1% and top 5% selections are identical. Maximum absolute first-order score differences range from `2.70e-6` to `3.31e-5`; the much larger maximum relative errors are driven by entries close to zero. The exact values, per-run elapsed times, reserved memory, and absolute memory counters are retained in the companion JSON.

## Limits

These results strengthen the evidence that chunk-wise backward cuts gradient-collection peak allocation and preserves the observed channel ranking across three layer depths and three training-text windows on one model. They do not demonstrate general numerical equivalence, other model families, other dtypes, downstream quality, inference speed, or a statistically broad benchmark. The three repeats are paired allocator measurements of the same deterministic input within each record, not independent model seeds. Identical allocator peaks across different windows reflect fixed tensor shapes, not identical gradient values. Wall time is too noisy and this workload too small to claim a speed benefit.
