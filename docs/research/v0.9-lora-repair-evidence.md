# v0.9 bounded LoRA repair evidence

## Result

A revision-pinned SmolLM2-135M candidate completed two seeded LoRA repair steps on
one real MLP down projection. Only 4,224 adapter parameters were trainable. Loss
decreased from 6.19560 to 6.19358, and the separately retained adapter serialized to
a 17,104-byte safetensors payload.

The base tensor SHA-256 was
`8d31efcdcbaff9a0827f8b1428c063939d5b65f88d9f84f444921c1c46219277`
both before and after training, directly proving that separate mode did not mutate
the source/candidate base weight. The adapter payload SHA-256 is
`7e6f316c89b48c7ce8df3201cb6ae7112ab930710c5b75e8dbf3387f5b437b8c`.

## Bounded protocol and resources

- Model: `HuggingFaceTB/SmolLM2-135M` at commit
  `93efa2f097d58c2a74874c7e644dbc9b0cee75a2`.
- Target: `model.layers.0.mlp.down_proj`; rank 2, alpha 4, dropout 0,
  learning rate 0.001, two steps, seed 42, 14 tokens.
- Training used FP32 on the RTX 3060. Peak allocated/reserved CUDA memory was
  579,348,992/599,785,472 bytes, peak RSS was 1,613,357,056 bytes, and measured
  repair wall time was 0.7821 seconds.
- A preceding FP16 attempt returned a non-finite loss and was rejected before any
  artifact publication. This validates the finite-loss and module-restoration path;
  it is not counted as a successful repair result.

The implementation also tests merge mode, which deliberately applies the learned
low-rank delta only to the in-memory candidate and removes the wrapper, plus failure
after a partial target setup, which restores the original module graph.

## Validity boundary

This smoke run proves bounded mechanics, provenance, resource capture, separate
artifact export, and source-weight preservation on one model/module. It does not
show downstream perplexity recovery or general repair benefit. Those comparisons
belong to the automated iterative study with no-repair and one-shot baselines.
