# v1.8 post-surgery LoRA: larger randomized held-out test sample

## Result

The three-seed two-pass study selected step 127 for every run and beat the
source on the same fixed 64 test rows. This follow-up keeps the seed-42 repair
training and validation data unchanged, but evaluates source, pruned/no-repair,
and the validation-selected repaired artifact on 512 rows shuffled from the
distinct WikiText test split with selection seed 2026. The source and candidate
artifacts were reloaded before scoring. Exact selected rows, text digests and
split-file digest are recorded in the report.

| Arm | Mean token loss | Perplexity | Full artifact bytes |
| --- | ---: | ---: | ---: |
| Source FP16 | 3.45508 | 31.66080 | 272,437,465 |
| Pruned, no repair | 3.72457 | 41.45358 | 265,801,794 |
| Pruned, LoRA selected | 3.42003 | 30.57046 | 265,801,794 |

The sample contains 58,872 next-token targets. The selected adapter reduced
loss by 0.30454 nats versus pruning without repair and scored 0.03505 nats
below source on this sample. Checkpoint selection used the 64-row validation
set, not these test rows: step 127 reduced validation loss from 3.41664 to
3.12555; step 128 was slightly worse and was not selected. Repair trained
122,880 parameters for 444 seconds, with peak CUDA allocation of 778,641,920
bytes. The physically pruned artifact was 2.44% smaller than source. This
result says nothing about inference speed.

This is one optimization seed on one model, one pruning severity, and one
seeded sample from WikiText-2 test. It strengthens the earlier 64-row result,
but does not establish significance, task quality, equivalence across datasets,
or generalization across architectures. Repeat the larger test protocol across
adapter seeds and task-specific evaluations before making broader claims.

## Provenance and reproduction

The study uses the pinned Apache-2.0 SmolLM2-135M and pinned WikiText revision
with upstream CC-BY-SA-3.0/GFDL metadata documented in the [four-row
protocol](v1.8-lora-post-surgery-smoke.md). The raw dataset text is not
included. The test sampler uses a local seeded shuffle; the report records the
selection seed, selected rows and text hashes. Preflight confirmed no exact
token-sequence overlap between selected train, validation, and test examples.

```powershell
uv sync --extra hf --extra research --locked
.venv\Scripts\python.exe tools/run_lora_post_surgery_study.py `
  --output docs/research/v1.8-lora-post-surgery-128step-512test.json `
  --remove-channels 64 --examples-per-split 64 `
  --test-examples-per-split 512 --test-sample-seed 2026 `
  --max-length 128 --rank 2 --steps 128 --seed 42
```
