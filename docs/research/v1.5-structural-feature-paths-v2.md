# Structural feature-path protocol v2

## Question

Does the structural-surrogate study compare distinct learned architectures, and
does it select a candidate without using held-out test outcomes?

## Source audit and findings

The v1 source audit found that all named arms passed through the same
standardized linear regressor. The so-called MLP and Set Transformer arms
received the same pooled features; the Graph Surgeon arm added topology and
history aggregates. The resource calculation assigned arbitrary multipliers
by arm rather than counting the predictor's parameters. Therefore v1 did not
implement or compare an MLP, Set Transformer, or graph neural model, and its
resource figures were not physical measurements.

The v1 selector compared candidate MAE intervals on the `test` split and chose
an arm using those same results. This makes the reported held-out performance
selection-biased. The validation partition existed but was not used for
selection.

## Correction

Protocol v2 names the arms by the actual feature paths (`linear_pooled` and
`linear_topology_history`), keeps source-compatibility aliases for the v1 enum
members, selects only from validation MAE intervals, and reports test metrics
after the decision. It also counts the shared predictor's coefficients and
intercept consistently and labels memory/latency as analytical proxies rather
than physical benchmarks or proven upper bounds. The v1 protocol JSON is preserved and marked as
superseded.

The regression fixture trains on a signal available only to the
topology/history path. It confirms that this path can be selected from
validation data and that flipping only test labels changes reported test
performance without changing model selection.

## Result and claim boundary

The audit conclusion is **negative** for v1's claims of distinct structural
model families and unbiased architecture selection. This is a protocol and
software-correctness result, not a model-quality finding. The fixture is
synthetic and does not demonstrate Meta-Surgeon effectiveness, physical
optimization, or inference gains. No GPU or full-model experiment was run.

Further work should implement genuinely distinct learned representations,
compare them on provenance-verified physical mutation data with validation-only
selection, evaluate downstream candidate decisions, and measure inference
costs on target hardware. Until then, structural representation effectiveness
remains unproven.
