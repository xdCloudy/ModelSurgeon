# v1.0 performance regression evidence

## Result

All three version-1 performance profiles completed on the reference Windows consumer
workstation after the checked baselines were calibrated. The final confirmation runs
passed 18 of 18 budgets: seven small PR-lane CPU/GGUF budgets, seven larger consumer
CPU/GGUF budgets, and four CUDA memory/runtime budgets.

| `pr-cpu` | GGUF wall | 0.030687 s | ≤ 3.15 s | pass |

The omitted `pr-cpu` process-CPU result was exactly zero at Windows' process-clock
resolution and passed its 1.05-second ceiling. The local `pr-cpu` run proves fixture
execution but does not claim to calibrate GitHub-hosted Linux timing; that profile keeps
explicit cross-runner headroom and records the hosted runner's actual hardware in each CI
artifact.

## Hardware and protocol

- OS: Windows; architecture: AMD64.
- CPU: Intel Core i5-14600K identity string `Intel64 Family 6 Model 183 Stepping 1,
  GenuineIntel`; 20 logical cores.
- System memory: 68,422,938,624 bytes reported total.
- GPU: NVIDIA GeForce RTX 3060, 12,884,377,600 bytes reported VRAM, compute capability
  8.6.
- Hardware context ID:
  `hwctx_ed3b61c4fb5f43339f61d393f54c09cc00688c77c0298cb1279b95321c7ba958`.
- CPU and GGUF profiles used three repetitions. CUDA used five repetitions after cache
  cleanup/synchronization at each boundary. Peak memory was sampled every 5 ms.
- CPU fixtures streamed a deterministic byte pattern into SHA-256. GGUF fixtures used the
  real transactional writer, disk preflight, 256 KiB chunks, output-size reconciliation,
  and temporary output cleanup.
- CUDA allocated two deterministic 1024×1024 FP32 matrices, synchronized the real matrix
  multiplication, and checked a finite result.

Two sequential passes were used during calibration; the table reports the final pass after
thresholds were tightened. No profile ran concurrently with another performance profile.

## Boundary

These fixtures detect resource and runtime regressions in representative bounded paths.
They do not establish end-to-end model throughput, quality, cross-hardware equivalence, or
large-model memory requirements. Those claims remain covered by the model ladder, native
GGUF, llama.cpp, and iterative-search evidence suites.
