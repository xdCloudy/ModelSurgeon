# Qwen3.6-derived MoE GGUF 224-expert full-test stress study

This study tests the compression frontier below the previously measured 252-of-256 expert slice. It compares router-norm selection with one equal-size random selection generated by PR #736's in-tree surgery implementation.

## Results

| Artifact | Experts retained per layer | File reduction | WikiText-2 PPL | Source/candidate PPL retention | 98% floor |
| --- | ---: | ---: | ---: | ---: | --- |
| Source | 256 | — | 6.7090 ± 0.04243 | 100% | baseline |
| Router norm | 224 | 11.58% | 8.7952 ± 0.05828 | 76.28% | fail |
| Random seed 20261026 | 224 | 11.58% | 7.5839 ± 0.04910 | 88.46% | fail |

Both candidates physically removed 32 of 256 experts in each of 41 blocks and produced the same 19,199,501,568-byte artifact size, a reduction of 2,513,960,928 bytes from the 21,713,462,496-byte source. Neither candidate meets the configured 98% point-estimate PPL-retention floor. This compression level is therefore not acceptable under that quality constraint.

The random candidate's PPL point estimate is 1.2113 lower than router norm's on this exact model and corpus. The reported plus/minus bands do not overlap, but llama.cpp's propagated uncertainties are not formal confidence intervals. One random seed cannot establish a general selector ranking. The result is evidence against treating router-norm scores as a guarantee of quality retention at this aggressive prune ratio, and evidence that this random sample happened to be less damaging in this cell.

The 252-expert router-norm candidate remains a materially milder point on this frontier: its preceding full-test report records 1.45% file reduction and 98.53% source/candidate PPL retention. This study does not change that result or establish that the 224-expert candidate is deployable. The separate 252-expert GPU throughput study found intervals including zero and did not demonstrate a speed improvement; no throughput test was run for these 224-expert files.

## Protocol and limits

- Source: `Endy-Qwen3.6-CyberSec-35B-A3B-Q4_K_M`, source revision `eed558458ca9ff6972063c486c7f1ab9e0b0c93e`, SHA-256 `ed118e7768330eb440ddc8ade42a04005ecab37f131d7e84bb08d14d1e315ae1`.
- Dataset: complete pinned WikiText-2 raw test split, 580 chunks and 296,960 scored tokens. The archive and text hashes are recorded in the [machine-readable evidence](qwen35moe-gguf-expert-slicing-224-fulltest-2026-10-26.json).
- Runtime: llama.cpp `0.7.0-dev`, build 11804, commit `c7fc50941`, CPU-only on an Intel Core i5-14600K with 64 GiB RAM; `-c 512 -b 512 -ub 256 -t 12 -ngl 0 --chunks -1 --no-warmup --ppl-output-type 1 --log-colors off`.
- The source result is reused from the exact-hash, exact-dataset full-test baseline; both candidates were run to completion with exit code 0. llama.cpp logged unused tensors for parts of the model, so broader runtime or task compatibility is not inferred from successful perplexity evaluation.
- The source model is AGPL-3.0; model weights and dataset text remain local and are not included in this repository.

This is one model, one corpus, one router-norm candidate, and one random seed. It does not measure task accuracy, latency, throughput, memory savings at inference, repair, or generalization. Full details, output hashes, exact settings, and provenance are in the [JSON record](qwen35moe-gguf-expert-slicing-224-fulltest-2026-10-26.json).
