# Competitive technology acquisition matrix (initial audit)

**Audit basis:** ModelSurgeon `main` at `72cf8017d48669157dd6b51b7c2ad0a1917320a1`;
upstream revisions and repository licence metadata were resolved on 2026-10-25.
This is the first implementation-focused tranche of the continuing review, not a
claim that every listed upstream has completed a line-by-line audit. No upstream
code is copied by this change.

## Current ModelSurgeon boundary

The source audit found a real HF path from calibration and per-channel feature
collection through candidate measurement, structural surgery, reload, quality
gates, deployment measurement, and evidence publication. A signed Meta-Surgeon
can order candidates, but current search physically measures every candidate
before selecting the measured feasible result. Existing comparison records
include Meta-Surgeon, weight-magnitude, random, and no-guidance baselines. The
retained transfer evidence is negative or neutral, so predictions do not have
measurement authority and are not yet an optimization advantage. This is the
critical integration gap for this pass.

GGUF remains a separate typed path with explicit family/layout/codec contracts.
The current evidence proves physically written and reloaded candidates with
negative quality-gate outcomes; it does not establish broad MoE or quantized
model coverage. ModelSurgeon's own [goal-to-reality matrix](goal-reality-gap-matrix.md)
and [first-surgeon proof protocol](../first-surgeon-proof.md) retain the wider
implementation and evidence limitations.

## Change made from the research

The HF active-search comparison records two observational activation-aware
baselines. `activation_magnitude` ranks by the lowest finite pre-mutation
`activation_abs_mean`; `activation_weighted_magnitude` ranks by the product of
per-channel `weight_l2_norm` and `activation_rms`. The latter is a structured
candidate analogue inspired by WANDA's weight-magnitude × input-activation
score; it does not reproduce WANDA's per-weight masking algorithm. Both report
the chosen candidate's physical quality-gate result and regret beside existing
baselines. Neither changes which candidates are evaluated, the selected
measured candidate, the quality gate, or prediction authority. Missing or
non-finite features leave the respective baseline unmeasured. No upstream code
is copied, and no performance improvement is claimed.

The acceptance criterion for any future policy use is positive, uncertainty-
bounded reduction in physical evaluations at an equal feasible quality/size
frontier across held-out model identities, with random, weight-magnitude,
activation-magnitude and Meta-Surgeon comparisons on identical candidate sets.
Current evidence does not meet that criterion.

## GSQ/RCO audit outcome

The code audit pinned both repositories and confirmed their top-level Apache-2.0
licences. GSQ's custom autograd implementation saves and restores CUDA RNG state
to replay Gumbel noise during backward; its trainer learns scalar assignments
and group scales through layerwise reconstruction. RCO projects gradients onto
the budget tangent, retracts with a scalar shift, transports Adam's first
moment, and discretizes learned choices with dynamic programming. These are
useful algorithmic ideas, but neither released pipeline is a drop-in for
ModelSurgeon's Windows/consumer path. The only integration-safe next step is
isolated algorithm verification with ModelSurgeon's own artifact and evaluation
contracts; no upstream source or dependency is added here. GSQ's paper reports
low-bit scalar and GGUF results, while RCO's paper reports exact-budget search;
those are upstream results, not ModelSurgeon evidence ([GSQ](https://arxiv.org/abs/2604.18556), [RCO](https://arxiv.org/abs/2605.00649)).

## Next research tranche

The next implementation tranche should verify the RCO discrete budget solver
against exhaustive tiny assignments, then prototype whether a ModelSurgeon
GGUF quantization-plan adapter can use actual encoded byte costs rather than
average-bit proxies. GSQ's low-bit reconstruction should be evaluated only
after a memory-bounded CPU/GPU feasibility cell is defined. In parallel, trace
the actual LoRA recovery and llama.cpp conversion paths, record file-level
licence coverage, and sequence MoE changes around the already-open Qwen3.5 PR.
