# v0.7 native Q4_K_M MLP proof

## Outcome

Issue #162 completed a real, deterministic, model-wide native MLP surgery on the
Q4_K_M SmolLM2 artifact. The proof removed channels 0 through 255 from the coupled
gate, up, and down projections in all 30 transformer layers, changing the global
feed-forward width from 1,536 to 1,280. It did not create a full floating-point
model or tensor copy.

This is a systems proof, not a recommended pruning mask. The deliberately simple
channel choice caused a large quality regression; that negative result is retained
rather than hidden.

## Immutable inputs and operation

- source: `HuggingFaceTB/SmolLM2-135M` revision
  `93efa2f097d58c2a74874c7e644dbc9b0cee75a2`
- llama.cpp revision: `95b8e33e16bb9a60de780a70930ebf729db6a90a`
- input Q4_K_M SHA-256:
  `b505aa5616edb1a9d25a097be2350bb980896481003db33efd52a90019c3b7bf`
- output SHA-256:
  `97283bd5442c2395b74abe56b61113da5a63d43175e7daf0e817f0481c2543ec`
- removed channel set: `[0, 256)` in every layer
- seed for the matched requantization control: 1,729
- copy chunk ceiling: 1,048,576 bytes
- row working ceiling: 1,048,576 bytes

The plan contained 90 coupled tensor edits. All used encoded-copy paths: 60 Q5_0
gate/up tensors used whole-slice copies, 16 Q4_K down tensors used complete-block
copies, and 14 Q6_K down tensors used complete-block copies. No edit entered a
float decode/requantization path. This required a strict storage-only boundary:
Q5_0 can be indexed and copied, but it still has no claimed native float codec.

| Tensor count | 272 | 272 | 0 |

All 182 tensors outside the coupled edit set retained byte-identical SHA-256
digests. The executor reported zero row working bytes because every changed range
was copied as complete encoded blocks or slices. Process telemetry sampled 232
times at 10 ms: RSS started at 25,518,080 bytes and peaked at 243,830,784 bytes.
The 218,312,704-byte observed increase includes Python planning state, hashing,
writer buffers, and resident memory-mapped input pages; the peak remains below the
270,885,440-byte F16 artifact and no full FP16/BF16 model copy was constructed.

Three independent executions produced the same output SHA-256. A Windows telemetry
probe defect discovered during the proof was fixed by declaring the native process
API pointer types, so RSS is no longer silently unavailable on 64-bit Windows.

## Matched control and perplexity

Because the surgery used only encoded-copy paths, the identical-codec matched
requantization control correctly had zero touched ranges, zero bytes decoded, and
zero bytes encoded. Its artifact is therefore exactly the baseline; no synthetic
requantization loss is attributed.

Both perplexity commands used the canonical manifest
`tests/fixtures/llama_cpp_perplexity_v1.txt` (SHA-256
`253b0372fbfb8b2287a5e95456d565f94d136744dded9711ca17c8af65cfa664`),
context/batch/microbatch 128, six CPU threads, one chunk, no warmup, and zero GPU
layers. Both returned status 0 without timeout or log truncation.

The small canonical text is a smoke benchmark, not a population-quality estimate.

## External load and generation

Pinned `llama-cli` loaded the output and completed both the one-token validation
and a deterministic 32-token generation with status 0, no timeout, and no truncated
logs. The generation used seed 1,729, context 128, six threads, no GPU layers, and
the prompt `The most important property of a safe model optimizer is`. Baseline and
candidate stdout SHA-256 values were respectively
`f3e3809b88f98f50f82b0d3839f579faabb779be8c8320ce4b4b2c8e38211e23` and
`0e3fce1186412cc193a973fbfc0087623b0a11e451202c931b42dc0376991c33`.
