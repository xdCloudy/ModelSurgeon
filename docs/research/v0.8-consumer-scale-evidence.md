# v0.8 consumer-hardware scale evidence

## Result

The scale runner exercised model loading, graph/parameter analysis, bounded static
features, a reversible aligned-row mutation, and a short forward evaluation on the
three revision-pinned ladder models already present on the reference PC. The four
larger pinned checkpoints were not cached and network permission was unavailable;
they are recorded as `model_unavailable` failures rather than extrapolated results.

Peak columns are the maximum observed across stages, not additive deltas. The first
run pays cold Python/model setup costs, so wall-time comparisons this short are
descriptive rather than a fitted scaling law. All completed evaluation forwards
returned finite logits on CUDA. The runner writes no mutation scratch artifacts;
scratch-disk peak is therefore zero, while cache disk reports the immutable local
snapshot footprint.

## Protocol

- Reference host: Windows 11, 20 logical CPU cores, 64 GiB RAM, NVIDIA GeForce RTX
  3060 12 GB, driver 610.74, PyTorch 2.10.0+cu130.
- Each available model is loaded from its exact ladder revision in FP16 with local
  files only and Accelerate automatic placement.
- Analysis enumerates all parameter tensors, verifies the observed parameter count,
  and chooses the first MLP matrix.
- Features evenly sample at most 65,536 elements and compute mean, RMS, and maximum
  magnitude. Mutation zeros and restores the first complete row of that same real
  parameter, recording the aligned extent and restoration result.
- Evaluation tokenizes one fixed local prompt (11 tokens for the measured models),
  performs one inference forward, and checks every output logit is finite.
- RSS and PyTorch allocated/reserved CUDA memory are sampled every 10 ms around each
  stage. Cache bytes and zero scratch writes provide the disk accounting.

## Practical defaults

The checked policy uses available accelerator memory as a hard precondition:

- through 500M on a 12 GB-class GPU: FP16 `full_tensor`, 64 calibration tokens;
- 1B–1.5B: FP16 `tensor` mode, 32 tokens;
- roughly 4B: quantized accelerator `streaming`, 16 tokens;
- 7B on this host: CPU `streaming` with eight-token batches, or quantized GPU
  evaluation when an immutable compatible artifact is available.

These are conservative preflight defaults, not measured claims for the unavailable
rungs. The policy treats cards reporting at least 11 GiB usable memory as 12 GB-class
because firmware reservations can place a marketed 12 GB card just below 12 GiB.

## Validity boundary and completion status

The successful measurements cover 134.5M–494.0M parameters, not 7B. They do not
establish empirical scaling behavior above 500M, and the unavailable rows must not
be used to claim that the recommended modes fit or perform well. Completing the
large-rung evidence requires downloading the pinned 1B, 1.5B, 4B, and 7B snapshots
and rerunning the same local-only protocol. The benchmark implementation and failure
audit are complete; the 1B–7B empirical acceptance evidence remains pending that
external prerequisite.
