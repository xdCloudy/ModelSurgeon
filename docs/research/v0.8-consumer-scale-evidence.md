# v0.8 consumer-hardware scale evidence

## Result

The revision-pinned seven-model ladder completed loading, parameter analysis,
bounded static feature extraction, reversible aligned-row mutation, and a short
forward evaluation on the reference consumer PC. Every evaluation returned finite
logits. The 100M through 4.02B models remained on the RTX 3060; Accelerate placed
the 7.25B model across CUDA and CPU without disk offload.

## Protocol

- Reference host: Windows 11, 20 logical CPU cores, 64 GiB RAM, NVIDIA GeForce RTX
  3060 12 GB, driver 610.74, Python 3.12.13, PyTorch 2.13.0+cu130.
- Each model is loaded from its exact ladder revision in FP16, local-files-only,
  with Accelerate automatic placement. Duplicate non-safetensors weight formats
  are excluded from snapshot resolution.
- Analysis enumerates all parameter tensors, verifies the observed parameter count,
  and chooses the first MLP matrix.
- Features sample at most 65,536 exact integer-spaced, in-bounds elements and compute
  mean, RMS, and maximum magnitude. Mutation zeros and restores the first complete
  row of the same parameter, recording its aligned extent and restoration result.
- Evaluation tokenizes one fixed local prompt, performs one inference forward, and
  checks every output logit is finite.
- RSS and PyTorch allocated/reserved CUDA memory are sampled every 10 ms around each
  stage. The report also records placement, model-cache bytes, stage CPU/wall time,
  and scratch-disk peak.

## Practical defaults

The checked preflight policy uses available accelerator memory as a hard condition:

- through 500M on a 12 GB-class GPU: FP16 `full_tensor`, 64 calibration tokens;
- 1B–1.5B: FP16 `tensor` mode, 32 tokens;
- roughly 4B: quantized accelerator `streaming`, 16 tokens;
- 7B on this host: CPU `streaming` with eight-token batches, or quantized GPU
  evaluation when an immutable compatible artifact is available.

The measured FP16 4.02B run fit entirely on the GPU, but the conservative default
retains headroom for calibration workloads larger than this one-forward protocol.
The FP16 7.25B run required automatic CPU offload, validating the CPU-streaming or
quantized-GPU recommendation. Cards reporting at least 11 GiB usable memory are
treated as 12 GB-class because firmware reservations can put a marketed 12 GB card
below 12 GiB.

## Validity boundary

The study demonstrates bounded execution across 134.5M–7.25B parameters on one
consumer workstation. It does not establish cross-hardware performance, throughput,
quality after cumulative surgery, or quantized-artifact behavior. Timings are one
descriptive run per pinned model and must not be presented as confidence-bounded
comparisons. Those broader claims require separate replicated studies.
