# v0.7 pinned llama.cpp throughput evidence

Issue #159 was exercised with the pinned CPU-only `llama-bench` build and the F16
SmolLM2 GGUF used for #157 and #158.

## Measurement contract

The versioned report records the full command and raw bounded logs alongside:

- upstream build commit/number and reported CPU, GPU, and backend identity;
- prompt-processing and generation tokens/second;
- average, standard deviation, and individual latency/throughput samples;
- prompt, generation, effective context, batch, microbatch, thread, offload,
  repetition, and warmup configuration;
- streaming model SHA-256 and sampled peak child-process RSS/VRAM.

At the pinned llama.cpp revision, separate prompt-only and generation-only tests
share a context sized to the larger requested token count. The report therefore
records `context_tokens=max(prompt_tokens, generation_tokens)`, matching the
runtime implementation rather than inventing an unused context setting.

Child RSS is sampled by process ID at a bounded interval. A declared zero-offload
CPU run records zero VRAM. A GPU-offloaded run is rejected unless the caller supplies
a process-level VRAM probe, so missing GPU telemetry cannot be misreported as zero.

Comparisons expose speedup and memory deltas only when the complete configuration
and hardware/build identity match. Any drift is returned as named fields with no
performance ratios.

## Context and drift check

A separate five-repetition run increased prompt/effective context from 64 to 128
tokens while retaining the other settings. It measured 1848.297084 prompt tokens/s,
188.180449 generation tokens/s, and 311,410,688-byte peak RSS. The comparison
correctly refused speedup ratios and reported drift in `config.prompt_tokens` and
`config.context_tokens`. These short smoke measurements describe this PC and are not
a general hardware performance claim.
