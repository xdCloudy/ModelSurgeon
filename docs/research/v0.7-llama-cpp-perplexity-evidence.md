The manifest identity covers the sample content, count, dataset identity and
revision, split, tokenizer identity, and tokenizer revision. It deliberately does
not include the local file path, so moving an unchanged manifest does not change
its identity. File hashing and UTF-8 validation are streaming operations.

Before execution, the evaluator fingerprints every `tokenizer.*` GGUF metadata
entry and refuses baseline/candidate pairs whose actual tokenizer metadata differ.
Both commands are then generated from one immutable configuration; only the model
path changes between them. This enforces identical text, tokenizer, context, batch,
microbatch, thread, offload, chunk, and warmup settings.

## Real paired control

Both sides used the same F16 GGUF as a no-change control with context, batch, and
microbatch size 128; six CPU threads; zero GPU layers; one chunk; and no warmup.
Both runs returned status 0 with no timeout or log truncation:

| Observation | Baseline | Candidate |
| --- | ---: | ---: |
| Perplexity | 150.5799 | 150.5799 |
| Reported uncertainty | 70.04355 | 70.04355 |
| Delta | — | 0.0 |

An earlier integration attempt used a shorter version of the sample. llama.cpp
returned status 0 but emitted `you need at least 256 tokens to evaluate perplexity
with a context of 128` and no final estimate. The evaluator correctly reported both
measurements as unsuccessful and retained the raw diagnostic. The final interface
also preserves bounded stdout/stderr for non-zero exits, timeouts, truncation, and
unparseable successful exits.

This is a deterministic smoke/control benchmark, not a claim that the small public
sample estimates general model quality. The same manifest contract supports larger
pinned evaluation datasets without weakening the paired-comparison invariants.
