# v0.7 pinned llama.cpp validation evidence

Issue #157 was exercised against a real GGUF with an exact-revision, CPU-only
llama.cpp build on Windows. This is an external load and generation check, not a
synthetic subprocess fixture.

## Provenance

- llama.cpp revision: `95b8e33e16bb9a60de780a70930ebf729db6a90a`
- reported version: `0.2.0-dev (build 10597, commit 95b8e33e1)`
- compiler: Clang 22.1.8 for Windows AMD64
- build options: Release, Ninja, `LLAMA_CURL=OFF`, `GGML_CUDA=OFF`,
  `GGML_NATIVE=OFF`
- source model: `HuggingFaceTB/SmolLM2-135M` at revision
  `93efa2f097d58c2a74874c7e644dbc9b0cee75a2`
- converter: the pinned llama.cpp checkout's `convert_hf_to_gguf.py`
- generated model: F16 GGUF, 272 tensors, approximately 269.1 MB

The validator captured the complete executable path, `llama-cli --version`
command and output, expected and reported revisions, model path, generation
command, bounded stdout/stderr, truncation flags, return code, and timeout state.

## Forward/generation check

The bounded command used one predicted token, context size 128, six CPU threads,
zero GPU layers, seed 0, temperature 0, `--single-turn`, and `--simple-io`. The
prompt was `ModelSurgeon pinned validation.`

The report returned status 0 with `successful=true`, `timed_out=false`, and no
log truncation. llama.cpp loaded the generated F16 model, processed the prompt at
964.6 tokens/second, generated the requested token, and exited normally. The
only stderr diagnostic stated that GPU layers were ignored by the CPU-only build.

## Compatibility defects found by the real run

The first real probe exposed the current official version form
`(build 10597, commit 95b8e33e1)`, which the older parser rejected. After that
was corrected, the first generation run loaded and evaluated the model but stayed
in interactive mode until the timeout. The validator now accepts both official
version forms and passes `--single-turn --simple-io`, with regression coverage
for both behaviors.

This evidence establishes CPU load/forward compatibility only. GPU-offload and
quantized compatibility cells remain explicit work for issues #161 and #162.
