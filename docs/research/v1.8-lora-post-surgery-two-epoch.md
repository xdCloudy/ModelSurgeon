# v1.8 post-surgery LoRA: two-pass, three-seed study

## Result

The prior one-pass experiment selected its last update at step 64 for all
three seeds. This follow-up allowed 128 updates (two deterministic passes over
the same 64-row repair set), evaluating the same distinct 64-row validation
split after every update. All three seeds selected step 127; step 128 was
slightly worse on validation and was not retained.

| Arm | Mean test token loss | Mean test perplexity | Full artifact bytes |
| --- | ---: | ---: | ---: |
| Source FP16 | 3.51242 | 33.52926 | 272,437,465 |
| Pruned, no repair | 3.75717 | 42.82719 | 265,801,794 |
| Pruned, LoRA (mean of seeds) | 3.47891 | 32.42446 | 265,801,794 |

| LoRA seed | Test mean token loss | Loss recovered vs. no repair | Selected validation loss |
| ---: | ---: | ---: | ---: |
| 42 | 3.47536 | 0.28182 | 3.12555 |
| 43 | 3.47997 | 0.27721 | 3.12668 |
| 44 | 3.48140 | 0.27577 | 3.12528 |

Across the three adapter seeds, mean loss recovery was 0.27826 nats (sample
standard deviation 0.00316). All three repaired scores were below the source
score on this same 7,129-target test slice. This is a bounded comparison on one
fixed sample, not evidence of general quality improvement. The separate
[512-row follow-up](v1.8-lora-post-surgery-512test.md) evaluates the seed-42
repair on a larger shuffled test sample and likewise retains source and
pruning-only controls.

The physically pruned FP16 artifact remained 2.44% smaller than source. Repair
used 122,880 trainable parameters, 414–444 seconds per seed, and
778,641,920 peak allocated CUDA bytes on the RTX 3060. The 128-update budget
does not establish the optimal training duration; step 127 remains the selected
budget boundary and longer schedules are untested.

## Provenance and reproduction

The same pinned model and dataset revisions, row selections, no-repair arm,
channel score, and surgery parameters as the [one-pass study](v1.8-lora-post-surgery-one-epoch.md)
were used. Exact selected rows, text/file hashes, artifact manifests, and
runtime are in the canonical report files. Raw dataset text is omitted.

```powershell
uv sync --extra hf --extra research --locked
foreach ($seed in 42, 43, 44) {
  .venv\Scripts\python.exe tools/run_lora_post_surgery_study.py `
    --output "docs/research/v1.8-lora-post-surgery-128step-seed$seed.json" `
    --remove-channels 64 --examples-per-split 64 --max-length 128 `
    --rank 2 --steps 128 --seed $seed
}
```
