# v1.8 physical-prune and LoRA repair: 64-row, three-seed follow-up

## Result

Expanded the prior four-row smoke to 64 selected rows in each of the distinct
WikiText train, validation, and test splits. Each test artifact was evaluated on
7,129 next-token targets. The model, dataset, channel-removal rule, rank, learning
rate, maximum update count, output precision, and data selection order were held
constant across LoRA seeds 42, 43, and 44. Validation checkpoint selection uses
the token-weighted loss reduction introduced by the associated selector change;
the test split did not affect selection.

| Arm | Test mean token loss | Test perplexity | Artifact bytes |
| --- | ---: | ---: | ---: |
| Source FP16 | 3.51242 | 33.52926 | 272,437,465 |
| Pruned, no repair | 3.75717 | 42.82719 | 265,801,794 |
| Pruned, LoRA, mean across seeds | 3.70959 | 40.83722 | 265,801,794 |

LoRA improved loss over no repair in all three seeds:

| LoRA seed | Test mean token loss | Loss recovered vs. no repair | Validation loss, step 0 → selected step 16 |
| ---: | ---: | ---: | ---: |
| 42 | 3.70817 | 0.04900 | 3.41664 → 3.36396 |
| 43 | 3.71275 | 0.04442 | 3.41664 → 3.37002 |
| 44 | 3.70785 | 0.04933 | 3.41664 → 3.36499 |

Mean test-loss recovery was 0.04758 nats (sample standard deviation 0.00274) over
the three adapter initialization seeds. That recovered about 19% of the
0.24475-nat loss increase caused by pruning. The repaired models still had a
0.19717-nat higher loss than the source. All three selected the maximum tested
step, so the experiment does not establish a training-duration optimum.

Pruning reduced parameters by 2.47% and full FP16 artifact bytes by 2.44%. All
three source/no-repair/repaired evaluations used reloaded artifacts; candidate
directories each contain eight files and preserve the source tokenizer
vocabulary. Repair used 122,880 trainable parameters, 56–58 seconds per seed, and
778,641,920 peak CUDA allocated bytes on the RTX 3060. Timings are not inference
speed evidence.

This is stronger feasibility evidence than the four-row smoke, but remains one
135M model, one deterministic 64-row selection per split, one pruning severity,
and three adapter seeds. It does not establish generalization across examples,
architectures, or pruning policies, nor a competitive quality–compression
frontier. No distillation or inference-speed comparison is included.

## Provenance and reproduction

- The exact Apache-2.0 SmolLM2-135M revision, WikiText revision and upstream
  CC-BY-SA-3.0/GFDL metadata, split-file digests, selected rows, and runtime are
  retained in each canonical JSON record. Raw dataset text is not included.
- The pruning score is the global gated-MLP proxy documented in the [four-row
  study](v1.8-lora-post-surgery-smoke.md); no competitor source code was copied.
