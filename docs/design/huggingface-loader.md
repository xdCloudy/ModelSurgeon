# Safe Hugging Face loader

`load_causal_lm` is the single causal-language-model loading boundary. It imports the optional PyTorch and Transformers dependencies lazily, disables repository code by default, and places the complete model on CPU unless another supported device-map strategy is explicitly requested. Before loading, it inspects sharded checkpoint indexes. Local shard paths must remain within the model directory; any shard file already present must be regular. Hub indexes and shard names must belong to the exact snapshot selected for the load; cached shard-file symlinks may resolve only into that model's `blobs` directory.

The separate Safetensors metadata inspector applies the same traversal and containment checks before opening indexed shard headers. It supports normal Hub snapshot files and file symlinks into that model's `blobs` cache while rejecting escaping shard paths and symlinked parent directories. Shard-index JSON reads are bounded to 100 MiB.

The immutable `HuggingFaceLoadRequest` controls revision, dtype, placement, local-only access, and low-CPU-memory loading. For a Hub model, the loader resolves `config.json` at the requested revision, extracts the immutable snapshot revision from the Hub cache, preflights its sharded indexes, and loads the model at that same revision. The result keeps the loaded model separate from a primitive `HuggingFaceLoadProvenance` record containing the requested source, the requested revision, the resolved Hub commit (or local path identity), and every effective loader option. Supplying an explicit commit remains recommended when reproducibility across separate runs matters; resolving a moving branch or tag pins only the snapshot selected for that invocation.

The preflight narrows the affected Accelerate checkpoint-loading path used through this ModelSurgeon boundary. It does not change or repair Accelerate's own checkpoint APIs; callers that invoke those APIs directly must apply their own safeguards until upstream ships a patched release. Enabling `trust_remote_code` is an explicit security decision and is never inferred from model metadata.
