# ModelSurgeon v2.9 conversational security and approval boundary

Status: **closed as a bounded pre-product gate by issue #485**. The machine-
readable evidence record is [`v2.9-conversational-security-release-v1.json`](../research/v2.9-conversational-security-release-v1.json), and the executable gate is [`audit_v29_conversational_security_release.py`](../../tools/audit_v29_conversational_security_release.py).

This closes the v2.9 integration/evidence boundary. It does not turn the
conversational layer into a general security boundary, a hosted-provider
certification, or a product release.

## Frozen control-plane contract

- Consequential actions require an approval bound to the exact operation,
  capability scope, canonical plan ID/digest, material diff ID and changed
  paths, actor context, reuse policy, and expiry. Material replans invalidate
  the prior approval and expose a new diff before reapproval.
- The deterministic engine owns hard constraints, validated specs, approvals,
  tool capabilities, evidence status, transactions, budgets, source identity,
  and artifact publication. Provider text, prompts, metadata, and tool output
  remain untrusted boundary data.
- The shared policy resolver is fail-closed. Unknown, contradictory, missing-
  approval, malformed, stale, and isolation-failure states are non-executable;
  lower-trust text cannot authorize or relax a higher-trust constraint.
- Provider and tool requests cross copied boundaries with explicit trust zones;
  secret values are indirect and redacted from retained diagnostics and audit
  evidence. Negative, unsupported, failed, unknown, and inconclusive outcomes
  remain visible and replayable.

## Evidence and residual risk

The deterministic adversarial corpus contains 18 cases and 69 bounded variants,
including prompt injection, smuggling, forged evidence, secret/path attempts,
malformed output, authority conflict, and hostile tool/provider behavior. The
audit retains every observation, including unresolved limitations. Approval,
adversarial, isolation, replay, and direct API suites are listed in the
machine-readable record and are part of the release gate.

The following remain explicitly unsupported or unclaimed:

- operating-system containment for hostile in-process providers or handlers;
- live hosted-provider quality, credential, or endpoint security;
- complete resistance to future model encodings, Unicode confusables, or novel
  prompt-injection strategies;
- distributed or multi-writer campaign recovery;
- optimizer optimality, unmeasured model quality, and universal family/runtime
  support.

The gate therefore supports a bounded local, typed control-plane contract. It
does not certify arbitrary deployments or permit credentials in prompts,
fixtures, evidence records, or chat history.

## Verification checklist

Run from the repository root with a clean project-managed environment:

```text
uv sync --locked --extra dev
uv run --locked --extra dev python tools/audit_v29_conversational_security_release.py
uv run --locked --extra dev python tools/audit_adversarial_resistance.py
uv run --locked --extra dev pytest tests/test_v29_conversational_security_release.py -q
uv run --locked --extra dev pytest -q
uv run --locked --extra dev ruff check src tests
uv run --locked --extra dev mypy src/modelsurgeon
git diff --check
```

The audit fails closed on dependency identity drift, missing suite or document
evidence, weakened trust-zone or policy claims, dropped negative findings,
overclaimed process containment, unrecorded clean-environment evidence, or an
incomplete quality gate.
