# ModelSurgeon bounded conversational journey boundary

Status: **implemented as a bounded v3.0 integration slice for issue #488**.

The integration composes the v2.3–v2.9 typed APIs into one user journey:

- clarification and measurable intent remain provider-assisted but engine-
  validated;
- previews are read-only and carry the exact structured spec and plan identity;
- infeasible, unsupported, failed, unknown, and inconclusive outcomes remain
  visible and can be explained as typed alternatives or retained evidence;
- execution, resume, replan, and cancellation remain scoped by policy and
  approval; no provider output is an execution authority;
- campaign lifecycle and explanation reads reconnect by canonical identity and
  fail closed on stale state;
- provider diagnostics and campaign explanation commands use the same typed
  records as their Python counterparts; and
- direct CLI/Python optimize paths remain available and are covered by parity
  tests.

The new `ConversationalJourney` facade is intentionally not a second campaign
store or optimizer. It retains only a current typed turn and the digest of the
last trusted campaign snapshot. The SQLite campaign store, planner,
orchestrator, approval package, evidence query engine, and deterministic claim
renderer remain authoritative.

## Verified boundary

The issue-level acceptance tests exercise supported and negative journeys,
approval refusal before runtime, pause/resume, stale evidence context, plan
diffs, canonical explanation rendering, provider diagnostics, and CLI/Python
campaign parity. The existing v2.7, v2.8, and v2.9 audits remain required because
this slice composes those contracts rather than replacing them.

The slice does not claim a universal natural-language interface, hosted-provider
quality, distributed or multi-writer recovery, optimizer optimality, artifact
promotion without validated engine evidence, or hostile-process containment.
