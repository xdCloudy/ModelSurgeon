# ModelSurgeon v3.0 acceptance, security, and reproducibility review

Status: **bounded gate for issue #490; not an optimizer or deployment certification**.

The machine-readable matrix is [`v3.0-acceptance-matrix-v1.json`](../research/v3.0-acceptance-matrix-v1.json). The execution record is [`v3.0-acceptance-evidence-v1.json`](../research/v3.0-acceptance-evidence-v1.json), and the executable runner/audit is [`audit_v30_acceptance.py`](../../tools/audit_v30_acceptance.py).

## What this gate proves

The gate composes the v3.0 setup and conversational journey boundaries with the
earlier typed contracts. It runs focused tests for installation/configuration,
offline fixture setup, provider diagnostics, intent compilation, clarification,
negotiation, tools, campaign state, explanations, approvals, hard constraints,
provenance, artifact validation, direct APIs, recovery, replay, and adversarial
security. It also runs real project-managed CLI smokes for setup, no-LLM
diagnostics, offline provider refusal, and a no-LLM read-only optimize plan.

The trusted authority remains the deterministic ModelSurgeon engine and its
canonical records. Provider text, prompts, metadata, and tool output cannot
authorize surgery, relax a hard constraint, create an approval, or promote an
artifact. Unknown, unsupported, failed, and inconclusive results remain visible
in the evidence record.

## Reproducibility record

The execution record preserves the tested Git revision and branch, whether the
tree was clean at measurement time, Python and uv versions, locked dependency
setup, fixture-manifest digest, command timeout, output digests, command
results, quality-gate results, artifacts, budgets, known skips, and residual
limitations. Re-run the bounded gate from the repository root with:

```powershell
uv sync --locked --extra dev
uv run --locked --extra dev python tools/audit_v30_acceptance.py --run --full
uv run --locked --extra dev python tools/audit_v30_acceptance.py
```

The acceptance fixture manifest pins four upstream tiny model revisions and is
metadata-only: no model weights are committed or downloaded. The offline setup
cell therefore proves configuration and fixture-manifest handling, not model
quality or surgery capability.

## Security and negative evidence

The fixed v2.9 adversarial corpus and its audit remain part of the gate. Approval
scope, canonical plan/diff identity, actor context, expiry/reuse, secret
redaction, policy precedence, provider/tool isolation, artifact integrity, and
recovery tests are included. A failed run is written with the failing command,
output tail, and digest before the runner exits non-zero. The matrix and evidence
must cover explicit unsupported/unknown cells; dropping a negative cell fails
the audit.

## Explicit non-claims and known skips

- UX journey completion, a valid plan, or a no-LLM parity result is not
  optimizer correctness, optimality, or model-quality evidence.
- No CUDA execution, live hosted provider, hosted credentials, external local
  runtime, installer, hostile operating-system process containment, or
  distributed multi-writer recovery is claimed.
- The pinned tiny fixture manifest has no weights, so representative family
  surgery and measured optimizer capability remain unsupported by this gate.
- Existing environment-dependent pytest skips remain retained in the run
  output; they are not converted into support claims.
