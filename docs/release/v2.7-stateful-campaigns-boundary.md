# ModelSurgeon v2.7 stateful conversational campaigns release boundary

Status: **closed by issue #474**. The versioned evidence record is
[`v2.7-stateful-campaign-release-v1.json`](../research/v2.7-stateful-campaign-release-v1.json).
This is a bounded state and recovery release boundary, not a claim that the
full conversational product is generally available.

## Release surface

The v2.7 boundary makes the WAL-backed `CampaignStateStore` the single
canonical authority for a reconnectable campaign. Its versioned state binds
campaign/session/run identity, source-model digest, exact `OptimizationSpec`,
policy and approval, provider context, resource budget, lifecycle, outcome,
evidence cursor, transition version, and provenance. State transitions use
expected versions and atomic writes; evidence is append-only and cursor
addressed. Unknown schema versions, digest mismatches, malformed records,
stale writers, and corrupt databases fail closed.

The structured campaign APIs remain authoritative. A bounded conversation
summary may carry an exact state/evidence snapshot and untrusted transcript
context, but it is a transport view and cannot change a plan, approve work,
restore omitted history, or replace the store. Chat transcripts, provider
output, and UI reconnect success are not correctness evidence.

## Recovery and stale boundaries

The #473 matrix contains twelve deterministic cells. It compares direct/store
and summary/chat recovery using canonical state digest, evidence cursor,
retained evidence and artifact references, next action, hard constraints,
resource budget, source-model digest, and provenance. It covers pause/resume,
cancel, reconnect, restart, transcript loss, stale plans, expired approvals,
partial evidence, atomic SQL fault checkpoints, process restart, and direct/chat
equivalence. A separate-process reopen and injected write faults are explicit
evidence; a successful UI reconnect is not.

Stale proposals are refused and must be rebuilt from the current canonical
context. An expired approval is first recorded as expired, then resume is
refused until fresh approval is bound to the current specification. Cancelled
campaign replay, altered summaries, and stale evidence/context fail closed.
Supported interruption recovery retains committed state and evidence and
continues from the last valid boundary; it does not replay chat or duplicate
completed work.

## Operational limitations

This release guarantees one owning store instance per campaign in a local
process and SQLite WAL durability across the tested process-reopen boundary.
The in-process lock is local only. Multi-writer concurrency, distributed
coordination, cross-host failover, hostile-process containment, live provider
correctness, and model-quality recovery are unsupported or unclaimed. Direct
CLI/Python campaign APIs remain available independently of the conversational
layer.

The v2.7 boundary composes with, but does not replace, #415 progress
resumability, #427 autonomous orchestration, or #428 approval and
reproducibility packages. Those components retain their own execution cursor,
orchestration, approval, artifact, and reproducibility authorities.

missing stale/expiry evidence, recovery-matrix omissions, duplicate scope,
unsupported operational claims, missing examples, and incomplete quality-gate
records.
