# ModelSurgeon v3.0 conversational product boundary

Status: **bounded product release candidate for issue #491**.

This release integrates the v2.1–v2.9 conversational control-plane contracts
into one local-first journey. The release is intentionally evidence-bounded:
conversation is the primary product experience for the supported slice, while
direct CLI/Python automation, the `OptimizationSpec` contract and the
deterministic engine remain first-class and authoritative.

The executable checklist and machine-readable source of truth are:

- [`v3.0-product-release-v1.json`](../research/v3.0-product-release-v1.json)
- [`tools/audit_v30_release.py`](../../tools/audit_v30_release.py)
- [`tests/test_v30_release.py`](../../tests/test_v30_release.py)
- [`v3.0-acceptance-security-reproducibility-review.md`](v3.0-acceptance-security-reproducibility-review.md)

## Authority separation

```text
Text LLM / conversational harness
        │ typed, bounded request and evidence-grounded explanation
        ▼
OptimizationSpec / campaign / approval records
        │ validated contract
        ▼
Deterministic ModelSurgeon engine
        │ measured candidates, rollback, acceptance and publication
        ▼
Learned Meta-Surgeon predictions (never measurement or acceptance authority)
```

The Text LLM does not select tensors, relax hard constraints, invent
measurements, or promote artifacts. Chat history and provider text are not
canonical state. Predictions remain predictions until the deterministic engine
measures and validates them.

## Release states

The release manifest separates five states rather than collapsing them into a
single “supported” label:

- **Verified:** bounded local setup, typed journey, diagnostics, campaign and
  evidence contracts, migration, approvals, no-LLM operation, and direct API
  parity covered by repository evidence.
- **Experimental:** optional Text LLM/local provider execution, learned
  Meta-Surgeon behavior, physical surgery, search, and model-family coverage
  beyond the committed metadata fixtures.
- **Unsupported:** arbitrary shell/code/network tools, hostile-process
  containment, distributed recovery, automatic constraint relaxation, and
  universal architecture/device/deployment support.
- **Unknown:** model-quality and deployment results without a retained
  measurement on the exact target and hardware; live provider quality/security;
  and future, opaque or semantically mismatched records.
- **Deferred to v3.1:** scaling the learned Meta-Surgeon with new held-out
  evidence and revisiting broader runtime/packaging support only if it earns a
  new reproducible boundary.

## Release checklist

From a clean Python 3.12 environment:

```bash
uv sync --locked --extra dev
uv run --locked --extra dev python tools/audit_v30_release.py
uv run --locked --extra dev python tools/audit_v30_release.py --run
uv run --locked --extra dev pytest -q
```

The `--run` form executes every focused v2.0–v2.9, migration, acceptance,
lint, type and full-test command declared in the manifest. It returns a
non-zero result on the first failed command and does not rewrite release
evidence implicitly. Record its JSON output with the tested revision and
environment when producing a release candidate.

## Retained limitations

The release-candidate record keeps the metadata-only fixture limitation,
environment-dependent test skips, missing CUDA/llama.cpp/live-provider
measurements, and the unresolved hostile-process containment observation. A
future failure or inconclusive cell must be retained in the evidence record;
it must not be converted into “unsupported” or removed to make the checklist
green. See the [v2.9 residual-risk record](../research/v2.9-conversational-security-release-v1.json)
and the [v3.0 acceptance review](v3.0-acceptance-security-reproducibility-review.md).

This boundary does not claim optimizer optimality, model-quality improvement,
universal model support, or a GUI installer.
