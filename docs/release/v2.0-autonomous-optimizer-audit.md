# ModelSurgeon v2.0 autonomous optimizer release audit

Status: bounded release boundary verified by the machine-readable record in
[`docs/research/v2.0-autonomous-optimizer-release-v1.json`](../research/v2.0-autonomous-optimizer-release-v1.json).

This is a control-plane and research-evidence release boundary. It freezes the
public schemas and claim limits for the autonomous optimizer; it is not a live
model benchmark publication and does not publish model weights.

## Capability classification

| State | Release meaning |
| --- | --- |
| Verified | The typed schema, deterministic identity, validation, provenance, or fail-closed decision is covered by repository evidence. |
| Experimental | A bounded implementation or prior research path exists, but general model-quality or deployment claims are not established. |
| Unsupported | The requested format, family, runtime, provider, or artifact path is outside the verified boundary and must stop with a retained reason. |
| Unknown | The required external artifact, measurement, runtime, or reproduction fact is absent and must not be guessed. |

The complete model/format/runtime classification is machine-readable in the
release record. In particular, exact-format and exact-runtime evidence does not
transfer to a neighboring model family, quantization, host, or provider.

The shipped classifications are:

- **Verified:** bounded plan/resume, objective/plugin boundary, and benchmark
  publication gate on the declared Python/schema surfaces.
- **Experimental:** physical autonomous optimization and repair/quantization/
  runtime measurements on separately declared, host-bound cells.
- **Unsupported:** generic unlisted-family optimization and live provider or
  remote model-quality benchmarking.
- **Unknown:** clean-environment reproduction of every external v2 cell.

## Frozen release surfaces

- `OptimizationSpec` and objective/plugin records remain versioned and
  fail-closed. Hard constraints cannot be traded for a soft reward.
- Optimize plans, approvals, cursors, artifacts, and reproducibility packages
  retain source identity, budgets, configuration, and rollback lineage.
- The v2 benchmark contract retains all cells and requires confidence-bounded,
  deployable evidence plus independent audit/replay before publication.
- Direct Python and CLI workflows remain the supported automation path. The
  conversational/provider layers are bounded control-plane adapters and do not
  provide optimization authority.

## What this release does not claim

No live benchmark, CUDA run, hosted provider run, signed package, clean archive
installation, or licensed reference model publication was performed for this
boundary. These are release-pipeline or future-campaign actions. Missing
inputs and negative results remain explicit rather than being summarized as
success.

## Verification checklist

Run from the repository root with the project-managed runtime:

```text
uv run --locked --extra dev python tools/audit_v20_release.py
uv run --locked --extra dev pytest tests/test_v20_release.py tests/test_v2_benchmark.py tests/test_optimization_package.py tests/test_user_workflow_docs.py -q
uv run --locked --extra dev ruff check .
uv run --locked --extra dev mypy src
uv run --locked --extra dev pytest
```

The machine-readable record lists the dependency commits, evidence paths,
research protocol, known skips, compatibility sources, and required commands.
The audit rejects missing paths, altered dependency identities, incomplete
capability states, claimed live evidence, failed quality-gate entries, or
non-empty critical findings.

## Compatibility and post-v2 policy

Schema versions and protocol revisions are part of persisted identity. Additive
fields require an explicit schema revision or compatible migration; changing a
meaning, outcome, or decision rule requires a new protocol revision. Older
records remain readable only when their declared migration is deterministic.
Unknown and unsupported outcomes are never upgraded by a migration.
