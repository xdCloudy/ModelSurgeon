# v3.0 packaging and setup guidance

The v3.0 conversational product is released as a bounded Python package and
repository workflow. It is not a Windows installer, a protected `Program
Files` deployment, or a promise that optional model runtimes are installed.

## Reproducible install

Use Python 3.12 and the locked dependency set:

```bash
uv sync --locked --extra dev
```

For model-specific workflows, add only the required optional surface:

```bash
uv sync --locked --extra dev --extra hf       # Hugging Face/safetensors
```

The optional local GGUF adapter is not installed by the project lockfile.
`llama-cpp-python` currently pulls the unmaintained `diskcache` package, which
has an unsafe pickle-deserialization advisory and no patched release. Provision
that runtime separately only from a reviewed source, and never expose its
cache directory to untrusted writers.

The package build is reproducible from the checked-in metadata and lockfile:

```bash
uv build --out-dir dist
uv run python tools/verify_release_artifacts.py --dist dist --tag v1.0.0
```

The existing release workflow builds both sdist and wheel, verifies metadata,
attests the archives and installs the wheel into a clean Python 3.12
environment. The v3.0 product boundary does not silently change the package
version or publish a new tag; release publication remains a separately
approved maintainer action.

## First run

Initialize a user-owned data root without downloading models:

```bash
uv run modelsurgeon setup init \
  --data-dir ./modelsurgeon-data \
  --fixture tests/fixtures/tiny_hf_models_v1.json \
  --offline --min-free-gb 0.000001 --json
```

The setup layout keeps these concerns separate:

```text
Surgeon Tensors/  learned Meta-Surgeon artifacts
Text LLM/         optional conversational model
Models/           user/target models
Campaigns/        active and completed canonical campaign state
Evidence/         retained measurements and explanations
Artifacts/        staged outputs
Config/           modelsurgeon.toml
```

The fixture manifest is metadata-only. It pins model-family/revision metadata
for offline contract checks but does not download or commit weights. A real
campaign must supply an immutable model revision, compatible runtime,
hardware profile, measurement budget and retained evidence.

## Direct automation and no-LLM mode

Conversation is optional. These paths remain supported and do not require a
text model or provider credential:

```bash
uv run modelsurgeon provider diagnostics --no-llm --json
uv run modelsurgeon optimize --no-llm --json
uv run modelsurgeon migrate INPUT.json --output MIGRATED.json --json
```

The Python APIs use the same `OptimizationSpec`, deterministic engine,
campaign, approval and evidence contracts as the conversational journey.

## What setup does not prove

Successful setup does not prove CUDA, `llama.cpp`, hosted-provider quality,
model-family coverage, optimizer quality, or artifact safety for an unmeasured
target. Unsupported and unknown outcomes remain explicit and fail closed.
