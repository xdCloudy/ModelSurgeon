# v2.2 provider-layer release boundary

Status: bounded release boundary verified by the machine-readable record in
[`docs/research/v2.2-provider-layer-release-v1.json`](../research/v2.2-provider-layer-release-v1.json).

This boundary closes the v2.2 provider-layer milestone as control-plane
infrastructure. It does not announce `modelsurgeon chat`, a universal hosted
provider, or live model-quality evidence. Core ModelSurgeon planning and
execution remain provider-neutral; direct CLI and Python callers remain the
supported no-LLM path.

## What is frozen

- The typed provider contract owns interpretation, clarification, explanation,
  capability discovery, budgets, cancellation, failures, and provenance only.
- Local GGUF, compatible endpoint, and hosted adapters are bounded adapters
  behind that contract. Their deterministic fixture results are protocol
  evidence, not optimization or natural-language quality measurements.
- `none` is the default provider kind. Missing optional adapters, missing
  credentials, malformed output, timeout, cancellation, and budget failures
  fail closed with retained typed outcomes.
- Hard optimization constraints, source immutability, deterministic planning,
  evidence acceptance, artifact publication, and rollback remain owned by
  ModelSurgeon.
- Provider secrets stay outside canonical settings, provenance, diagnostics,
  prompts, and reproducibility records.

## Conformance boundary

The complete matrix is maintained in the machine-readable release record and
the generated table in [`docs/testing/provider-conformance.md`](../testing/provider-conformance.md).
The four explicit no-LLM unsupported cells are structured output, timeout,
token budget, and resource budget. Refusal, pre-cancelled request handling,
and deterministic provenance remain supported boundary behaviors for the null
provider. No unsupported cell is promoted to a support claim.

## Verification checklist

Run from the repository root with the project-managed runtime:

```text
uv run --locked --extra dev python tools/audit_v22_provider_release.py
uv run --locked --extra dev pytest tests/test_v22_provider_release.py tests/test_provider_conformance.py
uv run --locked --extra dev ruff check .
uv run --locked --extra dev mypy src
uv run --locked --extra dev pytest
```

The release record lists the exact dependency commits, focused evidence tests,
core modules checked for provider-specific imports, and documentation paths.
The audit is intentionally fail-closed if a dependency, matrix cell,
unsupported rationale, or evidence path is removed.

## Known limits and retained negative evidence

No hosted service, credential, live endpoint, local model-quality benchmark,
or representative-family runtime benchmark was run for this boundary. The
endpoint and hosted cells are deterministic transport-protocol tests only.
The local provider requires an explicitly installed `llama-cpp-python` runtime
and a licensed, pinned GGUF fixture; unavailable runtimes and missing or
malformed model metadata remain unsupported or failed outcomes. These limits
are retained rather than converted into a v2.2 support claim.
