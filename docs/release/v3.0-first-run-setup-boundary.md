# v3.0 first-run setup boundary

Status: issue #486 implementation evidence; not a general installer release.

This boundary covers the local-first setup and first-run contract. It proves
that the repository can initialize a separated, user-owned data layout, use
the existing supported fixture manifest without network access, preserve the
direct no-LLM CLI/Python path, and retain explicit negative setup outcomes.

## Supported evidence

- Python 3.12 core CLI runtime on the current Windows checkout.
- Local/offline initialization using
  `tests/fixtures/tiny_hf_models_v1.json` as a metadata-only fixture manifest.
- Separate `Surgeon Tensors`, `Text LLM`, and `Models` directories.
- Read-only diagnostics for missing directories.
- Permission, insufficient-disk, missing-fixture, provider-key, and offline-
  provider cells with stable outcome codes.
- Secret-free canonical JSON setup reports.

## Not claimed

- A Windows installer, `Setup.exe`, protected installation path, uninstall
  flow, or package-manager integration.
- Downloading or validating model weights through setup.
- Universal Hugging Face, GGUF, `llama.cpp`, CUDA, macOS, or Linux runtime
  support.
- Any hosted provider, credential availability, or optional local provider
  runtime merely because setup initialized successfully.
- That the metadata-only tiny fixture proves support for every architecture,
  model size, quantization, device, filesystem, or provider.

## Reproduction

Run from a clean checkout with Python 3.12 and the locked development
environment:

```powershell
uv sync --extra dev --locked
uv run pytest tests/test_setup.py tests/test_provider_configuration.py tests/test_config_io.py -q
uv run modelsurgeon setup init `
  --data-dir .\work\setup-audit-data `
  --fixture tests\fixtures\tiny_hf_models_v1.json `
  --offline --min-free-gb 0.000001 --json
```

The test suite uses temporary directories and monkeypatched filesystem probes
for negative permission/disk cells; it does not chmod or delete user paths.
The CLI smoke uses a disposable work directory. Preserve its JSON output with
the commit revision, Python version, platform, and declared budget when using
it as external evidence.

The recorded Windows run is committed in
[`v3.0-first-run-setup-evidence.json`](../research/v3.0-first-run-setup-evidence.json).
