# ModelSurgeon v2.6 bounded conversational tool-calling release boundary

Status: the typed tool contract and its five prerequisite boundaries are
recorded in the machine-readable
[`v2.6 release record`](../research/v2.6-bounded-conversational-tool-release-v1.json).
This is a bounded control-plane release boundary, not a claim that the
conversational product or live provider integrations are generally available.

## Release surface

The text model can request only four capability-scoped operations:

| Tool | Access | Required boundary |
| --- | --- | --- |
| `inspect_model` | read-only | strict input/output schema and inspection budget |
| `preview_plan` | read-only | intent/spec identity and preview budget |
| `query_evidence` | read-only | bounded cursor, record count and evidence budget |
| `execute_approved_plan` | consequential | plan digest, matching approval, trusted policy and transaction commit |

Each definition has an owner, schema version, strict JSON schema, deterministic
tool identity, hard wall/memory/evaluation/output budgets, and explicit failure
semantics. Unknown tools, versions, capabilities, fields, identities, or budget
expansions are refused before a handler is reached. The request schema is
version 1; the grounded result envelope is version 2.

The consequential input references an existing plan and approval. It cannot
name tensors, removal operations, commands, callbacks, providers, paths, or
model sessions. Approval is checked outside the tool arguments and cannot be
overridden by model text or metadata. Read-only transactions never receive an
engine mutation participant. Consequential work must use the existing
transaction participant and explicit approval/commit boundary; rollback,
cancellation, timeout, stale handles, replay, and unsafe retries remain typed
negative outcomes.

## Grounding and negative evidence

`ToolResult` keeps trusted outcome and provenance fields separate from bounded
raw failure payloads. Canonical evidence requires an immutable source digest,
evidence ID, and UTC observation timestamp supplied by the engine. Unverified
and unavailable evidence cannot be presented as measured evidence. Failed,
unsupported, unknown, refused, timed-out, and cancelled results remain
serializable and replayable with deterministic request/result identities.

The versioned adversarial corpus covers arbitrary shell/code requests, path
traversal, secret exfiltration, prompt-injection and metadata smuggling,
malformed schemas, forged or contradictory measurements, and replayed IDs.
Secret-shaped diagnostics are redacted before retention. The corpus is fixture
evidence for the boundary; it is not live model, campaign, provider, or shell
evidence.

## Direct APIs and limitations

Direct Python and CLI workflows remain independent of the conversational
dispatcher and do not require a provider. The release does not claim live
hosted-provider calls, credentialed endpoints, model-quality measurements,
campaign execution, or operating-system process isolation. Handlers run in the
host process and resource enforcement is cooperative; hostile third-party code
would require a separately supervised process and audited IPC boundary.

## Verification

Run from the repository root with the project-managed Python 3.12 runtime:

```text
uv run --locked --extra dev python tools/audit_v26_tool_release.py
uv run --locked --extra dev pytest tests/test_v26_tool_release.py tests/test_conversational_tools.py tests/test_conversational_dispatcher.py tests/test_conversational_transaction_boundary.py tests/test_conversational_adversarial_corpus.py tests/test_optimization.py -q
uv run --locked --extra dev ruff check .
uv run --locked --extra dev mypy src
uv run --locked --extra dev pytest
```

The audit rejects missing evidence paths, altered prerequisite commits,
allowlist drift, unbudgeted tools, missing approval/transaction policy,
incomplete outcome vocabulary, claimed live evidence, and omitted isolation
limitations.
